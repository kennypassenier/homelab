# Admin dashboard: adoption plan for kp-themes 11.0.0

Merged from five page-mapping reports (home/activity, stacks, backups/jobs, host/metrics, settings/chrome).
Read-only analysis: nothing was run or measured; every line count is an estimate. All paths are relative to
`admin/web/js/` of the kp-themes-11 worktree unless noted. kp options are named as in `/home/kenny/Projects/kp-themes/js/*.d.ts`.

## 0. Reading guide

* **Section A** = drop-in swaps (kp replaces home-made code, same look and behaviour, no decision for the owner).
* **Section B** = visual changes and new use cases, grouped into 14 demo topics `feat-kp11demo-1..feat-kp11demo-14`. Nothing in B is built before its demo is approved.
  Variants are options, not choices the owner must make: the demo sets the default (rule "choices are defaults"). Demos are shown in `formal` first.
* **Section C** = backend work. **Section D** = open component gaps (kp lacks it or does it badly). **Section E** = defects found on the way. **Section F** = waiting on kp-themes (being built there; adopt after the kp release). **Section G** = order of work. **Section H** = counts.
* Corrections from the kp-themes owner (applied): side drawer, `.kp-kv` copy, diff hunk classes and `newpill` already exist (step-kp11-44 to step-kp11-46, step-kp11-24); virtual lists are frozen as "Don't do" (kp FEATURES.md TH42), so no windowing anywhere; heat/chart/graph migrations are ours.
* IDs are stable: `step-kp11-1..`, `feat-kp11demo-1..feat-kp11demo-14` (items inside a topic: `feat-kp11demo-1.1`), `ask-kp11be-1..`, `gap-kp11-1..`, `fix-kp11-1..`. Reports' original IDs are not reused.
* **11.0.0 breaks in source: none** (no theme name, no `setTabbarBadge` call, no Barlow/Inter in js/css, in any of the five groups). Only stale tests: see fix-kp11-4.
  When `tabbar.js` is adopted never pass `max` (exact counts, UI_PRINCIPLES section 3).
* Dedupe rule: a replacement found in several groups appears once, with every page it touches. The pages list uses the sidebar names:
  Apps (`home.js`), Stacks (`overview.js`), Inbox (`needsyou.js`), Notification rules (`notifications.js`), Activity, Stack hub (`stack.js`), Map (`fleetview.js`),
  Apply, Update (+ `pinupdate.js`), Presets, Retired, Backups, Calendar (`backupcalendar.js`), Restore, Schedules, Jobs, Host, Log/Console, Metrics, Firewall, System, Settings, Passkeys, Secrets, Shell, App chrome.
* **Earlier decisions that still hold** (`docs/admin/KP_THEMES_ADOPTION.md`, feat-kpadopt-1): the Map's look never changes (kpa-14: graph.js would change node colour, label placement and the Show-all bar), so **feat-kp11demo-2.1 is only built if kp-themes ships a fixed node colour and a centred-label option**; until then feat-kp11demo-2 covers feat-kp11demo-2.2-feat-kp11demo-2.5 around the existing drawing. The hover card keeps its own placement (kpa-9). The three `sortableTable` tables (kpa-17) were kept for page filters, stack groups and Live view sort controls; A/E items that move them onto a datatable must carry those over (filters → `filter`/`query`, groups → `data-kp-row-group`, catalog rows → `table-reset-sort`).
* Note on the reports: group 3 listed "type-the-name confirmation" as a kp gap. It is not: `components.js` has `attachTypeConfirms`, `buildTypeConfirm`, `openConfirmation(btn,{typeName})` (see step-kp11-16).

### feat-kp11demo-1 Activity and Jobs timeline: gantt + heat + History datatable

Replaces `paintTimeline` + pointer brush (activity.js:1189-1404, ~220 lines). Jobs variant: lanes = stacks, ghost bar from `queued_at` to `started_at`, brush filters the jobs datatable, `kp-gantt-open` -> `openJobDialog(id)`.
* **feat-kp11demo-1.2 Heat.** `heat.js setHeat(el,{rows:[{key:stack,label,cells:[{tone:'ok|bad|quiet|none',label,tip}]}],columns:14 days,summary,every,toggle,picked})`, events `kp-heat-pick` (filter History to that day) and `kp-heat-row` (filter to that stack). * **feat-kp11demo-1.3 History feed.** Recommended `kp-datatable`: `data-kp-expandable data-kp-expand-single`, `data-kp-row-group` per day with `data-kp-group-count` and `data-kp-folded` for old days, `data-kp-filter-mode="add"` (stack, actor, state), `data-kp-remember`, page sizes replace "Show N more" (activity.js:1730), `expand([keys])` opens a row from the timeline. * **feat-kp11demo-1.4 Job detail.** `steplist` (step-kp11-6), step breakdown as `stackbar.js setStackbar({parts:[{key,label:step,value:seconds}]})` ("where did the 12 min go"), failed operation error as `code.js setCode(el,{text,title,language,maxLines,truncated})` with Copy, `problems.js` `{what,why,remedy,command}` for the outcome alert, shrinking `timer-disc.js` for "about 4 min left" (uses `remaining()`/`estimateRange`), `tick.js` on KPI numbers.
* **Real data.** 14 days x ~20 stacks from `rows` (FeedRow.stack, state); `/data/history` start/end; `jobRows()` with `queued_at/started_at/finished_at`; `perDay`/`phase` entries.
* **Variants.** (a) gantt only; (b) gantt + heat above History; (c) Jobs as a second tab beside the table (`segmented`); (d) compare two runs of one operation (`compare.js`, "4 m 12 s vs median 3 m 40 s"); (e) `print.js` incident list; (f) `thread.js` incident notes.
